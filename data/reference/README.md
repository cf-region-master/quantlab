# data/reference · 参考数据（动态股票池 + PIT 行业分类）

来源：外部已验收数据集（聚宽 JoinQuant 采集），2026-09 导入。**这些文件不是本项目生成的**，
导入时按区间表形式保留了原始校验口径，便于复核。

## 文件

| 文件 | 内容 | 行数 |
|---|---|---|
| `universe_intervals.csv` | **PIT 指数成分区间表**：`index,symbol,name,opt-in,opt-out` | 4,033 |
| `trade_days.csv` | 交易日历（2020-01-02 ~ 2026-09-30） | 1,636 |
| `universe_check.csv` | 每个采样日三指数成分数（用于核对） | 4,908 |
| `industry_intervals.csv` | **PIT 行业区间表**：`instrument,sw1,sw2,sw3,start,end`（申万 2021 版命名） | 9,157 |
| `instruments.csv` | 全部出现过的股票 + 上市/退市日 | 5,431 |
| `industry_name_map.csv` | 聚宽命名 → 2021 版命名 的映射表 | — |

采用**区间表**而非逐日展开表：逐日版 `universe_daily.csv` 为 64.6 MB、`industry_history.csv` 为 33 MB，
而区间表合计仅 1.1 MB 且信息等价（源数据的往返自检已确认二者可互相还原）。

## 语义

```
某股票在 [opt-in, opt-out) 区间内属于该 index
```
- `opt-in` 为空 → 采样起点（2020-01-02）之前就已是成分股
- `opt-out` 为空 → 到采样终点仍是成分股
- **同一 `(index, symbol)` 可有多行** = 调出之后又被调回，是两段独立区间。
  这一点必须保留：压扁成一行会让重建出的成分数一路偏离
  （源数据第一版就踩了这个坑：沪深300 成分数从 301 掉到 271）。

## 源数据的验收结论（导入时未复算，如实转述）

1. **逐日成分数**：1,636 个交易日，csi300/csi500/csi1000 每天精确等于 300/500/1000，偏离 0。
2. **往返自检**：区间表反展开 vs 原始逐日快照，4,908 个 (日,指数) 全部一致。
3. **换手特征**：csi1000 纳入/剔除 1,133 次，约为 csi500（556）的两倍，符合小盘指数换手更高的特征。
4. **调样生效日**：源数据采用"第二个星期五的**下一交易日**实施"，符合中证指数官方规则；
   第三方来源 unliftedq 早一天，差异已定性，非数据错误。
5. **行业覆盖率**：70 个采样日覆盖率最低 100%；与客户端快照在 2026-09-30 逐只比对
   sw1/sw2/sw3 不一致均为 0/5220。

## 必须知道的边界

**2021-12 之前是申万 2014 版分类结构**（point-in-time 本来如此）。命名归一化只保证"当前"
与 pipeline 一致。跨 2021-12 做行业哑变量中性化会有类别断裂，需按 date 分段或显式映射，
并在报告中说明口径。

## 本项目内的用途

- `quantlab/data/universe.py`：把区间表展开为逐日 `date × code` 的布尔掩码（动态股票池）
- `quantlab/data/industry.py`：把行业区间表展开为逐日行业标签（供行业中性化）
- 二者都按 `data/clean` 的日历与代码集对齐，缺失一律暴露为 NaN/False，不静默填充
